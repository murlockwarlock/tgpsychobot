# Telegram Admin UX acceptance audit

This audit was performed against the PR #55 acceptance candidate and updated after the copy/content cleanup. The live candidate was treated as the source of truth; older screenshots were not used as an implementation specification.

| Issue | Candidate behavior | Status | Change | Regression coverage |
| --- | --- | --- | --- | --- |
| Global content-language navigation | Object cards had local tabs, but a legacy `ca:language` callback still existed as an inert compatibility route | Already fixed | Kept only as a compatibility response; no global preference is used by normal navigation | Object-local card tests |
| RU-only translation noise | Whitelist cards hid locale tabs when the bot mode was off | Already fixed | Preserved and extended to all Content status/completeness blocks | `test_object_card_exposes_locale_tabs_only_when_enabled` |
| General-settings language request | General settings had no language row | Still reproduces | Added `Язык: ✅/❌ запрашивать` backed by `telegram_language_selection_enabled` | `test_general_settings_exposes_existing_language_request_setting` |
| Default-language meaning | Language screen described fallback incompletely | Partially fixed | Added explicit default, enabled stored preference, and inactive stored preference semantics | language overview and runtime locale tests |
| Duplicate Content editors | The new card exposed `Медиа и общие настройки`, which entered the old editor as a second visible path | Still reproduces | One `Изменить: контент` entry now reuses the full editor; the old route remains only as stale-callback compatibility | Content card and save-return tests |
| Visibility on card | Visibility was only inside the old editor | Still reproduces | Added direct card toggle and same-card return | `test_visibility_toggle_returns_to_same_localized_card` |
| Direct link | Link appeared only in the old editor | Partially fixed | Added the ready-to-use Telegram deep link to the Content card | Content card/manual route check |
| `action_btn_text` | The field was shown for every Content object, although runtime reads it only for the legacy `start_message` action button | Partially fixed | Removed it from generic Content authoring; retained the scoped `start_message` legacy editor and runtime translation | action-button runtime regression suite |
| Old/new Content list count | The candidate list selected every Content row. On `psy5d2_db`, the old primary query returned 9 rows while the candidate returned 15; the four technical rows were `test_button`, `test_intro`, `test_results`, and `secret_test_outro`. `start_message`, `menu`, and `disclaimer` are legitimate special admin content. The reported exact 9/12 screenshot therefore came from an older intermediate filter and is obsolete for the current candidate. | Fixed | Canonical list includes user Content plus the three friendly special rows, excludes the four test-owned rows, and renders ordinary rows as `human title · stable ID` | Content label/card, 15-item list, and production query tests |
| Content resource rename/delete | Menu-button screen exposed destructive delete without reference preflight; no Content-card operation existed | Still reproduces | Added Content-card operations. Rename is blocked because public keys/deep links cannot be proven safe; delete reports dependencies, confirms, rechecks, and removes localized rows/media atomically | dependency-report test |
| Menu resource management duplication | `Кнопки меню` exposed add/rename/delete alongside placement | Still reproduces | Screen now owns visibility/order only; localized labels are opened through `Названия пунктов меню` | keyboard regression |
| Pagination | New authoring list used an 8/9 page window and old topic screens used five | Still reproduces | Standardized affected admin lists to 15 and named arrows `⬅️ Назад` / `Далее ➡️` | boundary/list tests |
| Nested navigation context | Card/list callbacks dropped page and locale context | Still reproduces | Page and locale are encoded in callbacks/state and survive edit/save/cancel | save-return and card navigation tests |
| Locale switch return | Local selection could lose the object context | Partially fixed | Locale callbacks return to the same object and page; page zero keeps the old callback shape for stale keyboards | object-local card tests |
| Save/cancel destination | Full Content editor returned to the old list | Still reproduces | Context-aware save/cancel returns to the same Content card; legacy sessions keep the old fallback | save-return tests |
| Session race | Delayed notification cleanup could run after Save/Cancel and produce a false lost-session error | Still reproduces | Session validity is checked after notification; closed editors are silently ignored and duplicate Save is safe | delayed-notification and duplicate-save tests |
| Formatted preview | Candidate escaped formatted HTML into visible source tags | Still reproduces | Valid Telegram HTML is rendered in preview; malformed markup is escaped safely | preview helper tests |
| Localized keyboard button identity | Runtime already translated labels while retaining Content keys | Already fixed | Preserved the existing `UserMenuBinding` key identity path | localized keyboard/callback test |
| Runtime fallback | Runtime already used locale then RU and omitted empty resources | Already fixed | Preserved existing behavior | media/text fallback suite |
| System-pack boundary | Dynamic rows were already skipped by system-pack import/readiness | Already fixed | No change to system pack workflow | pack/readiness regression suite |
| Whitelist | Topic, Content, Plan, menu labels, ReferralTemplate, and MediaLibrary were already explicit; tests/automations/followups were not tabs | Already fixed | Preserved whitelist and did not expand it | whitelist test |
| Language screen copy | The screen included a long fallback/preferences explanation | Fixed | Replaced it with default language, selector state, multilingual state, enabled languages, readiness, and only actionable warnings | compact language overview test |
| Perplexity pricing footer | Generic model renderer appended a RUB disclaimer to every provider | Fixed | Pricing is rendered only when provider metadata contains explicit pricing currency; Perplexity has no pricing block | Perplexity model screen test |
| Test button source | Main keyboard used `ui.button.test`, while the message filter and registry still used `content.test_button.button_title` | Fixed | `ui.button.test` is the sole user-visible label source; legacy Content row remains stored but is not editable/listed/registered | keyboard, filter, and registry journey test |

The current canonical Content path is now the same list/card/editor flow for multilingual OFF and ON. OFF removes locale controls and diagnostics; ON adds locale controls only inside supported object cards.
